# Roadmap

1. Foundation (completed Phase 0): documented monorepo, Turkish preference form, honest development receipt, health semantics, local PostgreSQL configuration, automated API checks and frontend checks.
2. Curated recipe slice (completed Phase 1): 24 recipes, validated domain schemas, metric/household units, immutable serving scaling, deterministic text/diet/time/pantry ranking, recipe list/detail/recommend APIs and Turkish result cards. No LLM or nutrition claim. Automated and live acceptance checks are recorded in VERIFICATION.md.
3. Ingredient intelligence and basket (completed Phase 2): shared registry, controlled dimensions and safe canonical conversion, independent recipe scaling, quantity consolidation, conservative pantry allocation, unknown/ambiguous statuses, optional policy and provenance. API supports multiple selections; UI presents one meal, acceptance, quantity review and a real ingredient basket preview with local checklist. Tests/actual checks are in VERIFICATION.md.
4. Accounts, Mutfağım and deterministic personalization (Phase 3 implemented/verified at the documented isolated-test level): initial Alembic schema, opaque-cookie accounts, saved preference/allergy constraints, quantity pantry editing, preparation audit and saved-stock baskets. Real PostgreSQL verification remains an explicit open deployment dependency.
5. Tencerem branding and hybrid AI decisions (Phase 4): optional structured intent parsing, safe candidate choice, grounded explanations, session refinements/repetition control and deterministic fallback. Curated recipes remain authoritative; arithmetic and safety remain deterministic. See AI_DECISION_ENGINE.md and VERIFICATION.md for implementation and verification limits.
6. Production readiness and evaluated decision quality (recommended Phase 5, not started): actual disposable PostgreSQL migration/concurrency/persistence verification; controlled live-provider quality/cost/privacy evaluation; HTTPS/secrets/backups, distributed abuse protection, recovery/ownership and deletion/export/retention. Acceptance requires observed PostgreSQL round trips/isolation, a versioned Turkish safety/intent evaluation set, reviewed provider data handling and spend controls. No retailer or generated-recipe expansion is implied.
7. Authorized retailer integrations: contractual/API access, product mapping confidence, freshness and unavailable-item handling. Acceptance: no unauthorized scraping, auditable price timestamps, reproducible comparison tests.
8. Deployment: CI, versioned migrations, secrets management, backups, monitoring, TLS, rate limits, privacy/consent policies, and restore tests. Acceptance: staging smoke tests, rollback and recovery exercise, security review.
9. Monetization: validate willingness to pay before subscription or affiliate infrastructure. Acceptance: transparent pricing, authorized partner arrangements, account/billing security, explicit consent, measurable retention and sustainable costs.

No date or commercial capability is promised by this roadmap.


Future AI generation is an optional later decision after curated recipe quality and domain validation prove useful. Phase 4 only interprets intent and chooses curated recipes; recipe generation remains out of scope.
